# Documento de Apoyo No. 13.3 – Arranque automático de los drivers del robot con systemd.

**Duración Estimada:** 30 minutos.

**Sesión:** Día 3 – 04/11/2026, bloque 2 (2:00 p.m. – 6:00 p.m.), al inicio del bloque.

En ROS 2 no hay nodo maestro; lo útil es arrancar directamente los drivers del robot. El archivo systemd/mr-robot.service del repositorio robots\_ws [4] define el servicio [1]; se agrega con git sparse-checkout y se copia a /etc/systemd/system.

| **Paquete / carpeta** | **Para qué sirve** | **Qué contiene** | **Dónde se usa** |
|---|---|---|---|
| `systemd/` | Arranque automático: al encender el robot, systemd lanza los drivers (mr\_bringup robot.launch.py) sin abrir terminales. No es un paquete y no se compila. | mr-robot.service (servicio systemd; trae comentada la línea para la Jetson Nano, que lanza el contenedor). | Solo el computador del robot. |

**~/robots_ws/systemd/mr-robot.service (AGX Orin / Raspberry Pi)**

```
[Unit]
Description=Robot movil SENA - drivers ROS 2 (mr_bringup robot.launch.py)
After=network-online.target
Wants=network-online.target
[Service]
Type=simple
User=robot
Environment=ROS_DOMAIN_ID=21
ExecStart=/bin/bash -lc 'source /opt/ros/humble/setup.bash && source $HOME/robots_ws/install/setup.bash && ros2 launch mr_bringup robot.launch.py'
Restart=on-failure
RestartSec=5
[Install]
WantedBy=multi-user.target
```

En la Jetson Nano el `ExecStart` lanza el contenedor (línea comentada en el archivo) con las mismas opciones de `run_nano.sh` [2].

**Terminal – robot**

```bash
# ajuste User y ROS_DOMAIN_ID
# agregar la carpeta systemd/ del repositorio (en la Jetson Nano: printf '/systemd/\n' >> .git/info/sparse-checkout && git read-tree -mu HEAD)
cd ~/robots_ws && git sparse-checkout add systemd
sudo cp ~/robots_ws/systemd/mr-robot.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now mr-robot.service
systemctl status mr-robot.service
# registro en vivo
journalctl -u mr-robot -f
# para trabajar a mano
sudo systemctl disable --now mr-robot.service
```

Prueba: reinicie el robot sin abrir ninguna terminal y, desde el PC, ejecute `ros2 topic list`: deben aparecer `/odom` y `/scan`.

> **Un solo driver por puerto:**
>
> Mientras el servicio está activo, no lance `robot.launch.py` a mano: habría dos nodos abriendo el mismo puerto serie. Deténgalo antes con `systemctl stop`.
