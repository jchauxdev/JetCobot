## 1. COMUNICACIÓN EN ROS 2

ROS 2 no tiene un nodo maestro: los nodos se descubren entre sí con el protocolo DDS/RTPS por multidifusión UDP [2], [1]. Dos equipos se comunican si están en la misma red y usan el mismo `ROS_DOMAIN_ID`, que fija los puertos UDP del dominio. La documentación de ROS 2 recomienda valores entre 0 y 101 [3].

## 2. VARIABLES DE ENTORNO (EN EL PC Y EN EL ROBOT)

**Terminal – PC y robot**

```bash
# en el escritorio (si no está instalado: sudo apt install gedit)
gedit ~/.bashrc
# por SSH o sin escritorio
nano ~/.bashrc
```

## Pegue al final del archivo las líneas del recuadro siguiente (solo las que no tenga ya), guarde (Ctrl + S en gedit; Ctrl + O, Enter y Ctrl + X en nano) y cierre el editor. Estas líneas no se escriben en la terminal: se cargan solas en cada terminal nueva.

**Contenido para ~/.bashrc (PC y robot) – se pega en el editor, no en la terminal**

```bash
# al final de ~/.bashrc (en la Nano: tambien se pasa con -e ROS_DOMAIN_ID en run_nano.sh)
source /opt/ros/humble/setup.bash
source ~/robots_ws/install/setup.bash
# segun la tabla del DA-13.1
export ROS_DOMAIN_ID=21
# 1 solo para practicar en un PC aislado
export ROS_LOCALHOST_ONLY=0
echo "ROS_DOMAIN_ID=$ROS_DOMAIN_ID  RMW=${RMW_IMPLEMENTATION:-rmw_fastrtps_cpp (por defecto)}"
```

## 3. PRUEBAS DE RED

### Prueba 1: talker / listener

**Terminal – robot**

```bash
ros2 run demo_nodes_cpp talker
ros2 node list
```

**Terminal – PC**

```bash
ros2 run demo_nodes_cpp listener
ros2 topic info /chatter -v
```

### Prueba 2: turtlesim remoto

**Terminal – robot (con pantalla o VNC)**

```bash
ros2 run turtlesim turtlesim_node
```

**Terminal – PC**

```bash
ros2 run turtlesim turtle_teleop_key
```

### Prueba 3: robot real

**Terminal – robot**

```bash
ros2 launch mr_bringup robot.launch.py lidar:=false
```

**Terminal – PC**

```bash
ros2 run teleop_twist_keyboard teleop_twist_keyboard
```

mr\_base aplica la última orden recibida y, si deja de llegar, frena tras `cmd_timeout` = 0,5 s.

## 4. DIAGNÓSTICO

*Tabla 1. Problemas frecuentes de red en ROS 2.*

| **Síntoma** | **Verificación** |
|---|---|
| `ros2 topic list` no muestra los tópicos del otro equipo | Mismo `ROS_DOMAIN_ID`; `ROS_LOCALHOST_ONLY=0`; firewall (`sudo ufw status`); aislamiento de clientes del AP |
| Los tópicos aparecen pero no llegan datos | QoS incompatible (`ros2 topic info -v`); en Docker falta `--network host --ipc host` |
| Video lento por Wi-Fi | Suscribirse al tópico `.../compressed` (DA-15.1) |
| Dos grupos se controlan entre sí | Dos parejas con el mismo `ROS_DOMAIN_ID` |
