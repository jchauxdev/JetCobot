## 2. FUNDAMENTOS

### 2.1 Espacio de trabajo, underlay y overlay

Un **espacio de trabajo** (*workspace*) es una carpeta con una subcarpeta `src` que contiene paquetes. `colcon` compila cada paquete y genera `build/`, `install/` y `log/`. Al ejecutar `source install/setup.bash`, los paquetes del espacio de trabajo se **superponen** (*overlay*) a la instalación de ROS en `/opt/ros/humble` (*underlay*): si un paquete existe en ambos, se usa el del espacio de trabajo [3]. `rosdep` lee el `package.xml` de cada paquete e instala con `apt` las dependencias que falten [5].

### 2.2 Un solo espacio de trabajo: ~/robots_ws

Todo el curso usa **un único espacio de trabajo,** `~/robots_ws`. En él conviven los paquetes del robot móvil (`mr_*`) y, si el equipo también trabaja con el cobot, los de la celda (`jc_*`): así la integración robot móvil – cobot (DA-21.1) compila en el mismo lugar, sin mezclar espacios de trabajo.

El código del curso se entrega en `mr_ws.zip` [8], en el repositorio del curso [6]. Ese archivo es una **reserva**: se descomprime en `~/mr_reserva` y **no se compila allí**. El espacio de trabajo se construye **paso a paso**: cada documento de apoyo, en su **Paso 0**, copia de la reserva solo los paquetes que va a usar, los compila y los explora. La reserva sirve además para comparar o restaurar un archivo dañado.

### 2.3 ¿En el PC o en el robot? En los dos

## 4. PROCEDIMIENTO (EN EL PC)

### Paso 1. Verificar (o instalar) ROS 2 Humble

**Terminal – PC**

```bash
# debe mostrar: Ubuntu 22.04.x LTS
lsb_release -ds
source /opt/ros/humble/setup.bash
# debe mostrar: humble
printenv ROS_DISTRO
```

Si `/opt/ros/humble` no existe, instale ROS 2 Humble con el procedimiento oficial [2]:

**Terminal – PC**

```bash
# verificar UTF-8
locale
sudo apt update && sudo apt install -y locales
sudo locale-gen en_US en_US.UTF-8
sudo update-locale LC_ALL=en_US.UTF-8 LANG=en_US.UTF-8
export LANG=en_US.UTF-8
sudo apt install -y software-properties-common
sudo add-apt-repository universe
sudo apt update && sudo apt install -y curl
export ROS_APT_SOURCE_VERSION=$(curl -s https://api.github.com/repos/ros-infrastructure/ros-apt-source/releases/latest | grep -F "tag_name" | awk -F'"' '{print $4}')
curl -L -o /tmp/ros2-apt-source.deb "https://github.com/ros-infrastructure/ros-apt-source/releases/download/${ROS_APT_SOURCE_VERSION}/ros2-apt-source_${ROS_APT_SOURCE_VERSION}.$(. /etc/os-release && echo ${UBUNTU_CODENAME:-${VERSION_CODENAME}})_all.deb"
sudo dpkg -i /tmp/ros2-apt-source.deb
# obligatorio antes de instalar ROS 2 en 22.04
sudo apt update && sudo apt upgrade -y
sudo apt install -y ros-humble-desktop ros-dev-tools
# humble
source /opt/ros/humble/setup.bash && printenv ROS_DISTRO
```

### Paso 2. Descargar el material de reserva

El material está publicado en el repositorio del curso, https://github.com/jchauxdev/JetCobot, carpeta `Portafolio_Robot_Movil_2026` (archivo `mr_ws.zip`). Descargue solo ese archivo y descomprímalo en `~/mr_reserva`, **fuera** del espacio de trabajo:

**Terminal – PC (en el robot se repite en el Paso 9)**

```bash
mkdir -p ~/mr_reserva && cd ~/mr_reserva
REPO=https://raw.githubusercontent.com/jchauxdev/JetCobot/main
wget $REPO/Portafolio_Robot_Movil_2026/mr_ws.zip
unzip mr_ws.zip
# README.md  docker  src  systemd
ls ~/mr_reserva/mr_ws
```

Sin Internet, copie `mr_ws.zip` desde la carpeta del portafolio y use el mismo `unzip`.

### Paso 3. Instalar de una vez todas las dependencias

**Terminal – PC (en el robot se repite en el Paso 9)**

```bash
sudo apt install -y python3-serial python3-flask unzip tree \
  ros-humble-navigation2 ros-humble-nav2-bringup ros-humble-slam-toolbox ros-humble-rplidar-ros \
  ros-humble-teleop-twist-keyboard ros-humble-xacro ros-humble-joint-state-publisher-gui
# solo la primera vez en el equipo (si ya se hizo, muestra un aviso)
sudo rosdep init
rosdep update
rosdep install --from-paths ~/mr_reserva/mr_ws/src --ignore-src -r -y --skip-keys "jc_interfaces"
```

`rosdep` lee los paquetes de la reserva e instala lo que necesitan, así no hay que repetirlo en cada documento. La opción `--skip-keys jc_interfaces` omite la única dependencia que no está en los repositorios de ROS: es un paquete del cobot que se agrega al mismo espacio de trabajo en el DA-21.1.

### Paso 4. Crear el espacio de trabajo ~/robots_ws

Si el equipo ya trabajó la celda del cobot, `~/robots_ws` ya existe: compruébelo y **no lo vuelva a crear**.

**Terminal – PC (en el robot se repite en el Paso 9)**

```bash
ls ~/robots_ws/src 2>/dev/null || echo "robots_ws no existe todavía"
mkdir -p ~/robots_ws/src
cd ~/robots_ws
colcon build
source install/setup.bash
```

> **Resultado esperado:**
>
> Si es nuevo: `Summary: 0 packages finished` y las carpetas `build/`, `install/` y `log/`. Si ya existía, `colcon` compila los paquetes `jc_*` que tenga.

> **Precaución:**
>
> No compile dentro de `~/mr_reserva` ni la cargue en `~/.bashrc`: es solo una copia de consulta. Para restaurar un archivo: `cp ~/mr_reserva/mr_ws/src/<paquete>/<archivo> ~/robots_ws/src/<paquete>/`.

### Paso 5. Cargar el entorno en cada terminal

Agregue al final de `~/.bashrc` las líneas que **no** tenga ya (revíselo con `cat ~/.bashrc`; si hizo la transferencia del cobot, las dos primeras ya están):

**Archivo ~/.bashrc – PC (en el robot se repite en el Paso 9)**

```bash
~/.bashrc
source /opt/ros/humble/setup.bash
[ -f ~/robots_ws/install/setup.bash ] && source ~/robots_ws/install/setup.bash
source /usr/share/colcon_cd/function/colcon_cd.sh
export _colcon_cd_root=~/robots_ws
```

**Terminal – PC (en el robot se repite en el Paso 9)**

```bash
source ~/.bashrc
```

La condición `[ -f … ]` carga el espacio de trabajo solo si ya está compilado. Las dos últimas líneas activan `colcon_cd`, que se usa en el Paso 6. Las variables de red de ROS 2 (`ROS_DOMAIN_ID`) se agregan en el DA-13.2.

### Paso 6. ¿Qué espacio de trabajo está activo en esta terminal?

En ROS 1, `roscd` llevaba a la carpeta del espacio de trabajo activo. En ROS 2 el espacio de trabajo activo es el que se cargó con `source …/install/setup.bash` en esa terminal (directamente o desde `~/.bashrc`), y se consulta con estos comandos [3], [4]:

*Tabla 3. Equivalentes en ROS 2 para saber qué espacio de trabajo está activo.*

| **Pregunta** | **Comando** | **Qué muestra** |
|---|---|---|
| ¿Qué espacios de trabajo están cargados? | `printenv COLCON_PREFIX_PATH` | La carpeta `install` de cada espacio de trabajo cargado, por ejemplo `/home/usuario/robots_ws/install`. Si no muestra nada, solo está cargado ROS 2 (`/opt/ros/humble`). |
| ¿Todas las rutas de paquetes, en orden? | `printenv AMENT_PREFIX_PATH \| tr ':' '\n'` | Primero los paquetes del espacio de trabajo (*overlay*) y al final `/opt/ros/humble` (*underlay*). |
| ¿De dónde sale un paquete? | `ros2 pkg prefix mr_base` | La carpeta de instalación del paquete: dice si viene de `~/robots_ws` o de `/opt/ros/humble`. |
| Ir a la carpeta de un paquete (como `roscd <paquete>`) | `colcon_cd mr_base` | Cambia a `~/robots_ws/src/mr_base` (requiere la configuración del paso anterior). |
| Ir a la raíz del espacio de trabajo (como `roscd`) | `colcon_cd` | Cambia a `~/robots_ws`. |

**Terminal – PC**

```bash
printenv COLCON_PREFIX_PATH
ros2 pkg prefix mr_base
colcon_cd mr_base && pwd
colcon_cd && pwd
```

> **Resultado esperado:**
>
> `/home/<usuario>/robots_ws/install`, `/home/<usuario>/robots_ws/install/mr_base`, `/home/<usuario>/robots_ws/src/mr_base` y `/home/<usuario>/robots_ws`.

> **Precaución:**
>
> Cargue un solo espacio de trabajo propio por terminal. Si `printenv COLCON_PREFIX_PATH` muestra varias carpetas (por ejemplo un espacio de trabajo viejo), `ros2` puede usar una copia distinta del paquete que usted está editando: revise las líneas `source` de `~/.bashrc` y abra una terminal nueva.

### Paso 7. Incorporar los primeros paquetes: mr_base y mr_sim

| **Se incorpora** | **Qué contiene** |
|---|---|
| `src/mr_base` | Driver ROS 2 del RoboClaw, herramientas `check_roboclaw` y `mover`, regla udev en `udev/`. |
| `src/mr_sim` | Robot virtual: emulador del RoboClaw por un puerto serie virtual y lidar simulado. |

**Terminal – PC (en el robot se repite en el Paso 9)**

```bash
cp -r ~/mr_reserva/mr_ws/src/mr_base ~/mr_reserva/mr_ws/src/mr_sim ~/robots_ws/src/
cd ~/robots_ws
colcon build --symlink-install --packages-select mr_base mr_sim
source install/setup.bash
# explore la estructura del paquete
tree -L 2 src/mr_base
# mr_base, mr_sim
ros2 pkg list | grep mr_
```

Permisos y nombre fijo del puerto del RoboClaw (la regla udev crea `/dev/roboclaw` [7]; el detalle está en el DA-12.3):

**Terminal – PC (en el robot se repite en el Paso 9)**

```bash
# cierre sesión y vuelva a entrar
sudo usermod -aG dialout $USER
sudo cp ~/robots_ws/src/mr_base/udev/99-mr-robot.rules /etc/udev/rules.d/
sudo udevadm control --reload-rules && sudo udevadm trigger
```

### Paso 8. Prueba sin robot: check_roboclaw con el RoboClaw virtual

**Terminal – PC**

```bash
# Terminal 1: RoboClaw virtual
ros2 run mr_sim roboclaw_emulator
# Terminal 2: diagnóstico contra el puerto virtual
ros2 run mr_base check_roboclaw --port /tmp/roboclaw_emu --segundos 3
```

> **Resultado esperado:**
>
> `Version      : USB Roboclaw 2x15a v4.2.8 (EMULADOR)`, la tensión de batería, el PID de velocidad de cada motor y el monitoreo de encoders durante 3 s. Detenga el emulador con Ctrl + C.

Con esto queda listo el **punto 5 del DA-10.1**: allí se repite el comando con el RoboClaw real conectado por USB (`--port /dev/roboclaw`).

### Paso 9. En el computador del robot

Cuando el computador del robot tenga Ubuntu 22.04 y ROS 2 Humble (carpeta 11), repita en él los Pasos 2 a 7. A partir de ese momento, cada **Paso 0** de los documentos siguientes se hace en los dos equipos, para que el PC y el robot tengan siempre los mismos paquetes. En la Jetson Nano el procedimiento cambia (contenedor Docker, DA-11.2).

## 6. SOLUCIÓN DE PROBLEMAS

*Tabla 5. Problemas frecuentes.*

| **Síntoma** | **Causa probable** | **Solución** |
|---|---|---|
| `wget` responde `404 Not Found` | URL mal escrita (distingue mayúsculas y minúsculas) | Copie la URL exacta del Paso 2; verifique en el navegador que el archivo existe |
| `ros2: command not found` | Entorno de ROS no cargado | `source /opt/ros/humble/setup.bash`; revise `~/.bashrc` |
| `Package 'mr_base' not found` | No se cargó `~/robots_ws/install/setup.bash` | Abra una terminal nueva; compruebe con `printenv COLCON_PREFIX_PATH` |
| `colcon_cd: command not found` | Falta la línea de `colcon_cd` en `~/.bashrc` | Paso 5 y terminal nueva |
| Se ejecuta una versión vieja de un paquete | Otro espacio de trabajo cargado antes | `ros2 pkg prefix <paquete>`; deje una sola línea `source` de espacio de trabajo en `~/.bashrc` |
| `check_roboclaw` no responde (`/tmp/roboclaw_emu`) | El emulador no está corriendo | Inícielo en otra terminal (Paso 8) |
